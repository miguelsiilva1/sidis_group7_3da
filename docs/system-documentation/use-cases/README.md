# Use cases in the distributed system

Every user story of the monolith, as the distributed system serves it: which service, which route, and how the request is served across replicas and services. The business rules (story, acceptance criteria) come from the [monolith's documentation](../../../docs_monolith/system-documentation/use-cases/); each page adds what the distribution changes, an SSD and an SD.

How requests are served, by kind (details in the [system documentation](../../README.md#7-replication-and-forwarding-peer-to-peer)):

| Kind                             | How                                                                                       |
| -------------------------------- | ----------------------------------------------------------------------------------------- |
| Read by key                      | the replica that does not hold the record asks its peers (`X-Data-Node` names the holder) |
| Read of a catalog                | every replica holds the whole catalog: answered locally                                   |
| Listing or report                | gathered from every replica (`...AcrossReplicas`)                                         |
| Create a record                  | stored on the replica that got it and copied to the next one (outbox)                     |
| Create or change a catalog entry | copied to every replica (outbox), the latest change wins                                  |
| Change a record                  | sent to a replica that holds it, copied to the other holder                               |
| Between services                 | contracts C1-C5 ([contracts](../contracts/README.md))                                     |
